# Krill for Magpie

在 Magpie 原生供应商界面分别接入 **Krill · 套餐** 和 **Krill · 余额**，查询套餐额度、共享钱包及今日官网统计，调用当前 Key 可用的模型。当前版本 **0.20.0**。包名保持 `opencode-krill-usage`，模型 Key 不限制前缀。

这是非官方插件，与 Krill 或 Magpie 运营方没有隶属关系。模型权限、额度和最终计费以 Krill 服务端为准。

## 安装

在 Magpie「插件 → 添加插件」中输入：

```text
github:Lovest20018/Magpie-Krill
```

也可以使用命令行：

```sh
magpie plugin add github:Lovest20018/Magpie-Krill
magpie plugin login krill
```

固定本版本可使用 `github:Lovest20018/Magpie-Krill#v0.20.0`；固定标签不会跟随默认分支更新。

安装后，在「供应商 → 添加供应商」选择「Krill · 套餐」或「Krill · 余额」，完成连接，获取并勾选所需模型后保存。登录表单位于供应商流程中。

套餐供应商保留 `krill` ID 和 `krill/模型ID` 引用，已有连接继续使用；余额供应商新增 `krill-balance` ID 和 `krill-balance/模型ID` 引用。更早的 `krill-usage` 连接不自动迁移或删除。

[GitHub Releases](https://github.com/Lovest20018/Magpie-Krill/releases) 同时提供 `.tgz` 安装包和 SHA256 校验文件。将包解压到固定目录，也可在 Magpie 添加其中的 `package` 目录。插件没有第三方运行依赖或安装脚本。

## 功能

| 功能 | 说明 |
| --- | --- |
| 共用官网登录 | 在套餐入口使用 Krill 邮箱密码/TOTP 登录一次，余额入口复用已登录账号并单独配置模型 Key |
| 独立 API Key 连接 | 只连接模型，无需网站登录；Key 不限制 `sk-` 等前缀 |
| 套餐额度 | 显示余额、本周额度、套餐总额、结转额度、积分和请求次数共享池 |
| 共享钱包及今日摘要 | 余额卡片显示账号共享余额、实际余额扣费和官网账号请求/token；不与宿主用量重复累计 |
| 原生额度展示 | 普通窗口的金额与百分比同步切换已用/剩余；部分异常保留其他有效数据 |
| 模型目录 | 从所选线路读取当前 Key 实际可用的模型，不从价格表扩充调用权限 |
| 模型能力 | 采用公开元数据的上下文、最大输出和已核实的推理能力；未知值不猜测 |
| 公开参考价格 | Krill 公开标准价乘以所选线路倍率，单位为 USD/百万 token |
| 模型调用 | 支持 Responses、Anthropic Messages 和 OpenAI 兼容 Chat Completions；保留流响应、工具调用和取消信号 |
| 推理和速度参数 | 声明已核实的思考档位与速度能力，并转发宿主实际交给插件的参数 |

## 登录与凭据

两个供应商各提供两种连接方式：

- **共用官网账号**：先在「Krill · 套餐」选择「邮箱密码登录（套餐、余额共用）」，支持 TOTP，模型 Key 选填，留空仅查额度；再到「Krill · 余额」选择「使用已登录的 Krill 账号」，填写并核验余额 Key、选择线路，无需再次输入密码或 TOTP。只有一个官网账号时直接复用，多个时明确选择。已有登录未出现时先刷新供应商列表。只用 LinuxDo 注册的账号，需要先在 Krill 官网设置网站密码。
- **API Key 连接（仅模型）**：Key 必填；读取所选线路的模型目录核验连接，不访问网站订阅接口。

网站登录凭据用于官网余额、套餐和统计，独立模型 Key 用于模型目录和推理。用户选择复用后，官网 JWT 由 Magpie 保存在对应连接中；密码、验证码和 pending token 不长期保存。纯 Key 连接不会自动关联官网账号。

账号添加、移除和重新登录使用 Magpie 原生流程。套餐重新登录需重填自己的 Key 和线路，留空仅查额度；关联余额连接下次读取用量时同步官网状态，保留自己的 Key、线路和标识。余额连接按 Key 指纹和线路区分，同邮箱不同 Key 不覆盖；同 Key、同线路切换登录方法更新原连接。套餐入口保留原有账号标识。网站登录过期不影响独立模型 Key，插件不自动续期。移除单个连接不会退出其他关联连接；需要全部退出时分别移除连接并重载插件。

## 共享钱包与今日官网摘要

信息集中在原生供应商卡片，不增加管理页面。套餐卡片保留本周、套餐总额、结转及余额；余额卡片显示账号共享钱包，以及「今日（北京时间）余额扣费 · 官网账号全部调用次数 / tokens」。今日是北京时间零点到查询时刻，与官网查询参数一致。

钱包来自 `/api/credits` 的 `balance_usd`；套餐卡片可使用套餐接口的 `credit_balance_usd` 作为独立新鲜余额回退。实际余额扣费来自 `/api/request-logs/quota-summary` 的 `total_credit_cost_usd`，不采用模型总费用或余额差值。请求数和 token 来自 `/api/request-logs/stats` 的 `total_requests`、`total_tokens`，**包括同一官网账号的其他 Key 和其他客户端调用**，不冒充当前 Key 的用量。

多个 Key 可显示同一个共享钱包，不能累加这些余额。未知数据保持未知，零和负余额按实显示；没有真实额度上限的钱包和今日统计不生成进度条。官网摘要不导入 Magpie 自己的用量总数或请求日志。首版不关联官网 `token_id`，Key 明细在官网查看。

余额和套餐随宿主调用 usage 重新读取，今日统计最多缓存 60 秒，跨北京时间午夜立即换日；同一网站 JWT 的并发查询合并，不按邮箱共享数据。接口独立失败，保留有效结果并在摘要提示，全部失败时明确报错，不以过期数据替代。宿主决定刷新时机，插件不后台轮询。

两个供应商区分接入用途，不改变服务端实际扣费规则。插件不配置套餐到余额的备用路由，也不修改官网 `allow_balance_fallback`。Magpie 自己可能将同名模型归入自动路由分组；需要固定供应商时选择完整 `krill/…` 或 `krill-balance/…` 引用，并检查宿主路由设置。只看统计时可用宿主「仅看用量」。

余额目录保留当前 Key 的 `/v1/models` 返回的全部模型，包括图片、视频、音频和私有分组；不按类型、公开余额标记或名称过滤，也不从公开价格表扩充权限。已知图片声明 `capabilities.output.image`，其他类型按已知信息声明，未知能力不虚构。

生图界面、MCP、任务及图片保存由 Magpie 处理。余额 loader 原样转发宿主发来的 `/v1/images/generations`、`/v1/images/edits`，支持 JSON/multipart、独立模型 Key 和取消，不主动生成、重试或下载图片。

**宿主限制：**截至 2026-10-17 核对的 Magpie [v0.1.1281](https://github.com/yetone/magpie/releases/tag/v0.1.1281)，[原生生图目录 `Drawers`](https://github.com/yetone/magpie/blob/v0.1.1281/internal/gateway/draw.go#L227) 仍排除普通插件供应商账号。图片模型已由插件列出，但能否进入原生生图/MCP 选择器仍需宿主接入，图片编辑的 multipart 模型识别也需验证。当前验证覆盖插件目录和图片请求传输，尚未验证宿主完整生图流程。

## 额度与配速

套餐窗口和共享钱包随宿主 usage 刷新直读官网；今日统计最多缓存 60 秒，刷新频率由 Magpie 控制。

- 周计费套餐优先排列为「本周 → 套餐总额 → 结转额度」，采用服务端报告值，不按套餐天数推算总额。
- 普通额度提供结构化金额和单位。例如上限 600、剩余 295.91 时，已用显示 `304.09 / 600 USD`，剩余显示 `295.91 / 600 USD`，百分比同步变化。
- 单套餐到期时间在卡片摘要显示；多套餐保留逐条北京时间到期说明。重置时间与套餐到期分别处理。
- 部分窗口数据缺失时，在套餐摘要标注「部分额度未知」，保留其他有效额度和余额；全部不可读时明确报错，不将缺失用量画成 0%。
- 多套餐到期、负剩余和超过上限的额外额度保留明确文字，这些金额文字不随模式切换。宿主可将比例限制到 0–100%；窄双栏长文字可悬停查看全文。

配速比较消费比例与周期时间进度。例如周期过去 50%、额度已用 35%，表示比匀速少用 15 个百分点。Magpie 已用模式显示负号，剩余模式符号相反。只有可靠的周期起止时间才提供配速所需信息。

多套餐、结转和余额无法合成可靠的单一账号使用率，因此额度窗口仅用于展示，不承诺某条周限用完就自动切换整个账号。卡片样式、列数和配速标签由 Magpie 绘制。

## 模型、思考强度与速度

Claude 模型使用 Anthropic Messages，GPT/Codex/OpenAI 推理模型使用 Responses，其余文本模型使用 OpenAI 兼容 Chat Completions。套餐目录排除公开元数据明确为非文本的模型；余额目录保留 Key 返回的全部模型，具体媒体调用由宿主处理。

上下文与最大输出采用元数据原值。例如 `1,050,000` 上下文可能在 Magpie 中显示为 1.1M。已识别的当前 Krill GPT 模型可提供 `low`、`medium`、`high`、`xhigh` 推理档位；其他模型按已核实能力提供，不为未知模型虚构档位。

速度与思考强度独立：Standard 使用默认速度，Fast 对应 `service_tier: "priority"`，Ultrafast 对应 `service_tier: "ultrafast"`。插件不默认开启加速档，也不从公开速度价格生成额外可调用模型。

速度能力与可选参考价格独立。首次公开元数据读取失败时，插件使用 2026-10-16 已核实的能力：`gpt-6.1-sol`、`gpt-6-astra` 提供 Fast/Ultrafast，`gpt-6-sol` 和三个 `gpt-5.6-*` 模型提供 Fast；仅适用于模型接口实际返回的基础 ID。成功读取的元数据优先，本次插件运行中之后读取失败时保留最近确认的能力，包括被禁用或移除的档位。该兜底不提供价格、上下文或最大输出，也不扩充未知模型的能力。

**速度切换采用 Magpie 原生模型选择器提供的入口。** 已核对 Magpie [v0.1.1281](https://github.com/yetone/magpie/releases/tag/v0.1.1281) 源码：普通插件声明 `priority` 后可提供 Fast，声明 `priority` 和 `ultrafast` 后可提供三档。宿主负责显示闪电开关和应用所选 `service_tier`，无需生成额外速度模型；使用该版本或更新版本。此次核对覆盖源码和上游回归用例，尚未执行该版本完整 GUI 和收费请求验收。

Magpie v0.1.1269 起已将插件声明的档位写入 Codex 模型目录，并在 Chat/Responses 转换时保留支持的 `service_tier`，API 接入也包含该能力。对应模型的 `service_tiers` 为空时，检查宿主和插件版本、模型刷新以及公开元数据是否撤销了档位。目录声明与客户端按钮显示需分别核对。

已核对的 Windows Codex 桌面版 `26.1013.3656.0` 还按登录类型限制速度 UI，普通 API Key 或空登录类型不会提供 Fast/Ultrafast。可在 Magpie 的模型选择器中设置速度，由宿主在请求中应用，不依赖 Codex 桌面端显示按钮；Magpie 的入口修复不改变 Codex 的登录类型限制。插件不改写 Codex 的 `auth.json` 或全局环境变量，不把第三方 Key 配置成 PAT 登录；该身份适配不在本项目计划内。

路由分组不会因成员声明 `serviceTiers` 就自动向 Codex 提供相同档位，分组行为需单独核对；普通供应商模型的入口修复不代表分组已支持。

## 价格与缓存

模型参考价为 **Krill 公开标准价 × 所选线路倍率**，不采用账号渠道或专属优惠覆盖。基础模型价格是默认速度参考价，不能当作 Fast/Ultrafast 切换后的结算价；长上下文、分时条件及账号优惠也可能影响实际费用。

公开价格缺失、无效、禁用、非 token 计费或读取失败时不提供虚假单价，不回用过期价格。Magpie 自己的默认价或用户手设价格不代表 Krill 价格已核实；最终费用在 Krill 官网核对。

目录在各供应商内按账号、Key 和线路缓存 60 秒，每个供应商最多 50 组；匿名公开元数据缓存 5 分钟。换 Key 或线路立即换缓存，元数据临时失败保留已知类型和输入能力，余额目录继续保留全部 Key 模型；不采用过期价格。缓存仅在内存，重载清空。

## 可选参数

在 Magpie 插件选项中配置：

```json
{ "timeoutMs": 12000, "maxConcurrency": 4 }
```

`timeoutMs` 为 1000–30000 毫秒，默认 12000；公开元数据与其他 JSON 查询采用同一超时设置，失败后保留已核实的速度能力，价格保持未知。推理使用 Magpie 的取消控制，不套用 JSON 查询超时。`maxConcurrency` 为 1–1000，仅在显式配置时声明；用户在宿主中的账号或供应商限制优先。
